# Process Analysis Knowledge

## What to extract
For every process capture: trigger, desired outcome, actors, steps, sequence, systems, documents/data, inputs/outputs, decisions, approvals, handoffs, waiting, exceptions, frequency, volume, duration, rework/error rate, SLA, sensitivity, controls, dependencies, and evidence.

## Common pain-point patterns
- repeated copy/paste or re-keying;
- high-volume repetitive rule-based activity;
- frequent switching between systems;
- email/chat-based approval without structured tracking;
- manual document classification/extraction;
- waiting for handoffs or missing information;
- duplicate reconciliation;
- report assembly from multiple systems;
- rework caused by validation errors;
- manual notifications/status updates;
- exceptions dominating the nominal “happy path”.

## Analysis questions
1. What triggers the work?
2. What is the business outcome?
3. Which steps are deterministic vs judgment-heavy?
4. Which systems hold the source of truth?
5. Where is data re-entered?
6. Which steps wait on people/systems?
7. What makes cases exceptional?
8. What controls or approvals must remain?
9. What volume/frequency/time/error evidence exists?
10. What happens if automation fails?

## Evidence rule
A conclusion should link to one or more reviewed facts. If evidence is weak, reduce confidence and ask a follow-up question.
